## 미해결 중요 문제

### 1. 복습 누적으로 새 학습이 영구적으로 멈춤

`src/learning/scheduler.ts`는 기한이 된 복습이 15칸을 먼저 전부 채우도록 하고, `src/learning/review.ts`의 성공 간격은 30일로 제한합니다.

검토자가 실제 콘텐츠와 실제 함수를 사용해 하루 한 세트, 전부 정답으로 1,500일을 모의 실행했을 때 **450/2,001문항에서 정체**했습니다. 마지막 신규 문항은 752일째였습니다. 단어는 N5 674개 중 86개, 문장은 N5 159개 중 62개만 보아 두 챕터가 N4로 진행하지 못합니다.

다음 작업: 장기 회귀 테스트로 재현한 뒤, 복습이 많아도 신규 문항과 챕터별 진행 몫을 확보하고 충분히 익힌 항목의 간격을 늘립니다. 전체 분량은 15문항을 유지하고, 실제 장기 실행에서 모든 챕터가 N4에 도달하는지 확인합니다. 신규 자리만 확보해 복습 적체를 무한히 키우는 해결은 피합니다.

### 2. 입력·문장 조립이 실제 콘텐츠에 없음

현재 로더 결과는 `choice=1,931`, `listen=70`, `input=0`, `arrange=0`입니다. 입력·조립 컴포넌트는 합성 테스트에서만 사용됩니다. 생성 문법도 모두 한국어 쓰임 선택 문제입니다.

다음 작업: 실제 문자·문법·문장 항목에 입력·조립을 연결합니다. 자연스러운 단위의 일본어 조각을 직접 작성하고, 조립 정답을 만들 수 있는지 검증합니다. 현재 검증기는 `options=['水','を','ください']`, `answer='学校へ行きます'`도 통과시킵니다.

입력 문제 연결 시 `InputQuestion.tsx`의 IME 조합 상태도 함께 처리해야 합니다. 일본어·한국어 변환 확정 Enter가 답안 제출로 처리되지 않는 회귀 테스트를 추가합니다. 현재 설치본에는 입력 문항 자체가 없어 기존 사용자 장애로 따로 판정하지 않았습니다.

### 3. 듣기 문항이 원문을 항상 먼저 보여 줌

`sentenceContent.ts`와 `Practice.tsx`는 일본어 음성이 있어도 듣기 70문항의 원문을 먼저 표시합니다. 따라서 듣기 이해 연습으로 구분되지 않습니다.

다음 작업: 일본어 음성이 있으면 원문을 숨기고 듣기로 답하게 하며, 답변 후 또는 명시적인 ‘원문 보기’로 공개합니다. 음성이 없으면 기존 텍스트 대체 흐름을 유지합니다. 두 분기를 실제 Practice 화면 테스트로 확인합니다.

### 4. 콘텐츠 ID 변경·재배정 검증이 없음

문법·문장 ID가 행 번호에서 생성되어 중간 삽입·재배열 시 같은 ID가 다른 개념을 가리킬 수 있습니다. ID와 lesson 링크를 함께 바꾼 재현에서도 `validateContent`는 오류를 내지 않았습니다.

다음 작업: 기존 ID를 보존하면서 명시적인 원본 ID 또는 기준 목록을 도입합니다. ID 삭제·이름 변경·다른 개념으로의 재배정을 실패시키고, 이 검사를 `validate:content`와 패키징 과정에 연결합니다. 기준 목록은 일반 빌드에서 자동 갱신하면 안 됩니다. 의도적인 콘텐츠 수정은 검토 가능한 기준 변경으로 기록합니다.

## 번역 수정 1건

`src/content/grammar/points.ts`의 `先生に文を直してもらいました。`를 ‘선생님께 문장을 고쳐 달라고 했습니다’로 옮겨, 실제로 도움을 받은 결과를 요청으로 가르칩니다. 이 문장은 문장 문제 정답에도 재사용됩니다. ‘선생님께서 문장을 고쳐 주셨습니다’처럼 결과가 드러나도록 고쳐야 합니다. 같은 문형의 두 번째 예문 번역도 함께 확인합니다.

## 검토에서 판정하지 않은 범위

- 실제 일본어 기기 음성 재생: 이 PC에 일본어 음성이 없습니다. 현재 음성 분기는 테스트로만 확인했습니다.
- 친구 PC의 설치·실행: 접근할 수 없어 검증 범위 밖입니다.
- 전문 교사·원어민 수준의 전체 교육 품질 인증: 그런 감수를 받았다고 표시하지 않습니다.

이 세 항목은 새로운 기능을 몰래 생략한 결정이 아니라 기존에 명시한 검증 한계입니다.

## 재개 순서

1. 위 중요 문제와 번역의 등급을 사용자에게 미치는 영향 기준으로 확정하고 실행 기록에 남깁니다.
2. 각 문제를 먼저 실패하는 테스트로 재현한 뒤 한 번의 수정 과정으로 해결합니다. 최종 검토자를 다시 호출하는 대신 회귀 테스트와 전체 테스트로 확인합니다.
3. `npm run typecheck`, `npm test`, `npm run validate:content`, `npm run build`, `npm run make`를 통과시킵니다.
4. 새 설치 파일로 업데이트하고 새 문제 유형·듣기 대체·진도 보존을 표본 확인합니다. 일본어 실제 음성은 기기 환경의 한계를 계속 명시합니다.
5. 이 문서와 설계서·검증 문서를 최종 결과로 갱신하고 커밋합니다. 실행 기록의 판단과 미룬 항목은 별도 문서에 보존한 뒤 계획 작업 폴더를 정리합니다.

계획의 구현 단계 1~10은 기록되어 있지만 **최종 검토 수정 단계는 아직 시작하지 않았습니다.** 다음 실행은 새 프로젝트를 만들거나 앞 단계를 반복하지 말고 이 문서부터 이어갑니다.
